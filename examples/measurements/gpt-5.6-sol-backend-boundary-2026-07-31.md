# GPT-5.6-sol backend boundary seed measurement

> Date: 2026-07-31
> Status: one controlled task set; insufficient for a general efficiency claim

## Question

Does the repository's `engineering-loop` skill improve a bounded backend defect
run with GPT-5.6-sol, or does the model already perform the same loop without
the repository skill?

The pre-registered primary quality measure was acceptance without a human code
correction. Token use, elapsed time, and retries were secondary measures.

## Fixed setup

| Field | Value |
|---|---|
| Playground revision | `5a7d3b325f714bb0cbc1b645ad61c7884ba533a9` |
| Codex surface | Codex CLI 0.143.0, ephemeral `exec` |
| Model | `gpt-5.6-sol` |
| Reasoning effort | `medium` |
| Sandbox | `workspace-write` |
| Task | Find and repair one uncovered inventory input-boundary defect |
| Variants | no repository skill; `engineering-loop` v0.2.0; `engineering-loop` v0.4.0 |
| Run order | lean skill, no repository skill, full skill |

Each variant started in a fresh Git repository containing the same playground
code. The task contract and acceptance criteria were identical except that the
two skill variants explicitly invoked `$engineering-loop`. The rubric remained
unread until every run completed.

Global personal skills were visible to every run. The no-repository-skill
variant chose five of them automatically; the two explicit skill variants used
only their installed project skill. This is part of the observed routing result,
not a clean “model with no instructions” ablation.

All variants:

- found the seeded zero-quantity boundary;
- preserved a failing regression before implementation;
- added the same two-line `quantity <= 0` guard;
- added one four-line regression test;
- passed the focused and complete backend suites;
- removed generated bytecode churn from the final diff;
- reviewed the final two-file, six-line diff; and
- reported the untested non-integer and boolean input risk.

The no-repository-skill variant used an exact error-message assertion. The two
skill variants asserted only the exception type. The rubric requires rejection
of the boundary but does not require a particular message, so all three were
accepted.

## Directional interpretation

This task does **not** show a quality advantage for either skill. GPT-5.6-sol
completed the requested engineering loop under all three conditions, and the
no-repository-skill run used the fewest reported tokens and retries.

The lean skill used about 2.9% more reported tokens than the control, while the
v0.2.0 skill used about 7.1% more. The lean version used about 3.9% fewer tokens
than v0.2.0, which is directionally consistent with successful instruction
compression, but one run cannot establish a stable saving.

The control's automatic selection of five broad global skills—including
repository-specific API and backend guidance unrelated to this fixture—shows a
separate routing problem. Its lower token total does not make that irrelevant
context desirable.

For a bounded, well-specified defect with strong `AGENTS.md` instructions,
GPT-5.6-sol may not need the lifecycle skill. Retain the skill only if repeated
frontend, infrastructure, ambiguous, or higher-risk tasks show quality,
consistency, or handoff benefits that justify its context cost.

## Limitations

- This is one seeded backend task, not an independent community replication.
- All runs could see the same personal global skill catalog.
- The CLI repeatedly reported a model-cache schema warning; no run failed, but
  the runtime was not warning-free.
- The setup copied untracked local Python bytecode into every disposable
  playground before its baseline commit. The variants remained comparable, but
  cleanup added environment-specific work and makes retry/time differences less
  generalizable. A playground-local `.gitignore` was added after the runs to
  prevent future standalone copies from capturing this noise.
- Elapsed time was recorded from CLI event timestamps to the nearest second.
- Cost and context-noise-line measurements were unavailable and were not
  estimated.
- The evaluator knew the variant after execution, although the resulting diffs
  were mechanically compared and the rubric was hidden during all runs.

## Next evidence

Repeat all three variants for the frontend and infrastructure tasks, rotate run
order, and run the protocol on at least one representative external repository.
Do not simplify or remove the skill based on this seed alone.
